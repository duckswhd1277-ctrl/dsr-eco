# HEAT NO 문서 최적화 스킬

완료된 구현을 프로젝트 문서에 반영하고, 사용자 가이드를 최신화합니다.

## 사용 시점

```
Issue #XX 구현 완료 후:
"문서를 최신화해줄래?"
→ 이 스킬 실행
→ README, soul.md, CLAUDE.md 업데이트
```

## 문서 업데이트 항목

### 1. README.md 검토
- [ ] "주요 기능" 섹션 - 구현된 기능 반영
- [ ] "사용 방법" - 변경된 UI/UX 설명 업데이트
- [ ] "3단계 매칭 로직" - 개선된 로직 설명
- [ ] "버전 히스토리" - 최신 버전 정보 추가
- [ ] 마지막 업데이트 날짜 갱신

### 2. soul.md 검토
- [ ] "핵심 기능" 섹션 - 새로운 기능 추가
- [ ] "개발 원칙" - 변경된 규칙 반영
- [ ] "피해야 할 패턴" - 새로운 제약사항 추가 (필요 시)
- [ ] 마지막 업데이트 날짜 갱신

### 3. CLAUDE.md 검토
- [ ] "효과적인 요청 방법" - 새로운 패턴 추가 (필요 시)
- [ ] "기대하는 응답 형식" - 업데이트 (필요 시)
- [ ] "특수한 상황" - 새로운 케이스 추가 (필요 시)

## 링크 검증

```
- ✅ .claude/ 파일 링크 유효 확인
- ✅ GitHub Issues 링크 유효 확인
- ✅ 파일 경로 정확 확인
```

## 구조 검증

```
- ✅ 마크다운 형식 정확
- ✅ 코드 블록 정확
- ✅ 목록 들여쓰기 정확
- ✅ 제목 레벨 일관성
```

## 예시: Issue #42 문서화

**Issue 제목**: "ux: 미리보기 테이블 행 수 선택 가능하게"

**README 변경**:
```markdown
### 주요 기능

📊 **OT 열처리 기준 미리보기**
- 테이블: 제조번호 | 작업번호 | 선경 | 거래처 | HEAT NO | 상태
- 모든 컬럼 정렬 가능 (↑/↓)
- ✨ **행 수 선택 가능** (10, 25, 50, 100개)  ← 신규
- 상태: ✅ 정리파일에 존재 / ⚠️ 신규
```

**soul.md 변경**:
```markdown
### 3. 사용자 친화적 결과 확인
- **미리보기**: OT 열처리 기준 테이블 표시
- **행 수 제어**: 사용자가 표시 행 수 선택 가능  ← 신규
- **정렬**: ... (기존)
```

## 산출물

**JSON 형식** (memory에 저장):
```json
{
  "doc_updates": [
    {
      "file": "README.md",
      "status": "updated|skipped",
      "sections_updated": ["주요 기능", "버전 히스토리"],
      "timestamp": "2026-06-12T..."
    },
    {
      "file": "soul.md",
      "status": "updated",
      "sections_updated": ["핵심 기능"],
      "timestamp": "..."
    }
  ]
}
```

## 주의사항

- ❌ 과도한 변경 금지 (필요한 부분만)
- ✅ 명확한 설명으로 사용자 이해도 향상
- ✅ 코드 예시는 최신 코드 기반
- ✅ 마크다운 형식 일관성 유지
